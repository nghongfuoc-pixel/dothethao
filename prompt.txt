## 4. Deploy trên GitHub với SQLite — có được không?

**Không trực tiếp**, cần phân biệt rõ:

- **GitHub Pages** chỉ host được file tĩnh (HTML/CSS/JS chạy trên trình duyệt). Nó **không chạy được Node/Express**, và cũng không thể ghi/đọc file SQLite lúc runtime → nếu chỉ dùng GitHub Pages, phần "đặt hàng"/"liên hệ" sẽ không lưu được gì thật, chỉ demo giao diện.
- Muốn backend + SQLite chạy thật với **ghi được dữ liệu liên tục (persistent)**, cần một nơi chạy server process, ví dụ: **Render, Railway, Fly.io, hoặc VPS**. GitHub chỉ giữ source code + CI/CD (GitHub Actions) để tự động deploy sang các nền tảng đó, bản thân GitHub không "chạy" app.
- Riêng **Vercel/Netlify (serverless)**: filesystem là tạm thời hoặc read-only ở production → SQLite ghi vào đó sẽ mất dữ liệu sau mỗi lần deploy/scale, không phù hợp.

→ **Kết luận**: SQLite hợp để phát triển local. Khi lên production thật (có đơn hàng thật), nên hoặc (a) deploy backend+SQLite lên Render/Railway có ổ đĩa persistent, hoặc (b) chuyển sang Postgres (Supabase) — xem mục dưới.

## 5. Đẩy file SQL của SQLite lên Supabase — được không?

**Được, nhưng cần chuyển đổi**, vì Supabase dùng **PostgreSQL**, không phải SQLite. Hai cú pháp có khác biệt (kiểu dữ liệu, `AUTOINCREMENT` → `SERIAL`/`IDENTITY`, số ít escape khác nhau...).

Cách làm:
1. Xuất schema + dữ liệu từ SQLite (`sqlite3 mydb.db .dump`).
2. Chỉnh sửa cú pháp cho tương thích Postgres (đổi kiểu `INTEGER PRIMARY KEY AUTOINCREMENT` → `SERIAL PRIMARY KEY`, bỏ `PRAGMA`, sửa `TEXT`/`DATETIME` nếu cần).
3. Chạy file `.sql` đã chỉnh trong **SQL Editor** của Supabase, hoặc qua `psql` kết nối tới connection string của Supabase.
4. (Có công cụ hỗ trợ tự động như `pgloader` nếu dữ liệu nhiều, nhưng với 1 shop nhỏ chỉnh tay là đủ.)

**Đề xuất kiến trúc production tối ưu, tận dụng cả GitHub lẫn Supabase:**
- Code frontend + backend để trên **GitHub** (source control).
- Dev/local dùng **SQLite** (nhanh, không cần cấu hình).
- Production: frontend build tĩnh deploy **GitHub Pages** (hoặc Vercel/Netlify), backend API + database chuyển sang **Supabase (Postgres)** — Supabase tự cấp REST/API, xử lý luôn phần lưu đơn hàng/liên hệ mà không cần tự vận hành server riêng.

Trả lời hai câu hỏi trước khi tiếp tục:

**Prisma là gì?**
Prisma là một **ORM** (Object-Relational Mapping) cho Node.js/TypeScript. Thay vì viết tay câu lệnh SQL, mình định nghĩa cấu trúc bảng trong 1 file `schema.prisma` (như file tôi đã tạo ở [backend-dev/prisma/schema.prisma](backend-dev/prisma/schema.prisma) với các bảng `Category`, `Product`, `Order`...), sau đó Prisma tự động:
- Sinh ra migration (script tạo/sửa bảng trong DB) từ schema đó.
- Sinh ra "Prisma Client" — một bộ hàm JavaScript để truy vấn DB an toàn, có gợi ý kiểu dữ liệu.
